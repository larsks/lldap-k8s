# lldap in kubernetes

An example kubernetes deployment of [lldap](https://github.com/lldap/lldap).

## Required configuration

You will need to populate `lldap/secrets.env` with the following variables:

- `LLDAP_JWT_SECRET` -- used for encrypting JWT tokens
- `LLDAP_LDAP_USER_PASS` -- password for `admin` user

The file is a simple `KEY=VALUE` environment file:

```
LLDAP_JWT_SECRET=some-random-string
LLDAP_LDAP_USER_PASS=super.secret.password
```

## Deploying with Kind

You can deploy this into a [kind](https://kind.sigs.k8s.io/) cluster:

1. Create the cluster:

    ```
    kind create cluster --config kind.yaml
    ```

    Note that `kind` will write admin credentials for the cluster into your current `kubeconfig` file. I like to start by explicitly using a local file for this by setting the `KUBECONFIG` environment variable *before* running the `kind create` command:

    ```
    export KUBECONFIG=$PWD/kubeconfig
    ```

2. Deploy the manifests into the cluster:

    ```
    kubectl apply -k .
    ```

When everything is running, the web interface is available at <http://localhost:17170> and the LDAP service is available at `localhost:3890`.

You can test the LDAP service using tools like `ldapsearch`:

```
$ ldapsearch -LLLx -b dc=example,dc=com -H ldap://localhost:3890 -D cn=admin,ou=people,dc=example,dc=com -w super.secret
```

## Viewing maddy queued messages

This project runs [maddy](https://maddy.email/) as a queue-only mailserver so that you can inspect the password reset emails generated by lldap.

### Viewing the queue

```
$ kubectl exec deploy/maddy -- find /data/state/hold_queue
/data/state/hold_queue
/data/state/hold_queue/e5c33e88.header
/data/state/hold_queue/e5c33e88.body
/data/state/hold_queue/e5c33e88.meta
```

### Viewing a messages

```
$ kubectl exec deploy/maddy -- cat /data/state/hold_queue/e5c33e88.body | ./scripts/qprint
```
